VaultGate's first release: a self-hostable file vault where only the right people get in, files are encrypted before they are stored, personal data is caught before it leaves, and every action is accounted for. It covers the roadmap through **M12.6** (see the README's Roadmap). The agent milestones (M13 and later) are not started.

**It pairs with [vaultgate-frontend v0.1.0](https://github.com/flaviocavalcantet/vaultgate-frontend/releases/tag/v0.1.0)**, the web app (commit f081804). This release's local cluster runs that frontend and its browser tests.

- `ghcr.io/flaviocavalcantet/vaultgate-api:v0.1.0`

## What's in it

- **Identity (M1):** sign-in through the organization's OpenID Connect provider (Keycloak locally); users and groups kept in PostgreSQL.
- **A streaming vault (M2):** uploads and downloads go through the gateway with single-use intents. Each file is encrypted with its own data key (envelope encryption with KMS) and streamed to S3 in parts, so memory stays flat at any size.
- **Access policies (M3):** allow and deny rules by group, network and time window; deny wins, and everything is checked again at the gateway.
- **Personal-data scanning (M4):** a worker scans every upload for emails, Brazilian CPF numbers and payment cards. Findings quarantine a file until an administrator releases it.
- **Sharing (M5):** links for one recipient each, with an expiry and a download limit. An outside recipient proves their address with an emailed code; a VaultGate user signs in.
- **Audit and tracing (M6):** an append-only, hash-chained audit log, and OpenTelemetry traces across the API, the gateway and the scanner.
- **Kubernetes (M7, M12):** a local k3d cluster synced by Argo CD, images published by commit, and the gateway autoscaled on transfers in progress (KEDA).
- **Load testing (M8):** Locust scenarios with published results and a smoke run in CI.
- **PKI and secrets (M9):** a certificate authority with an offline root, keys in OpenBao, TLS 1.3 between every hop, and short-lived database credentials.
- **Security auditing (M10):** a threat model and an audit report, mutual TLS between the services, rate limits, transfer limits, distroless images, and ZAP and negative checks against the running system.
- **Node enrollment (M11):** certificates for external nodes through the API. First trust comes from admin approval, a Keycloak client, an enrollment token, AWS instance identity or TPM attestation.
- **Frontend support (M12.5):** an exact CORS allow-list, downloads a browser can follow, and the frontend deployed by the chart.
- **Folders (M12.6):**
  - Folders, with names unique in a folder; files and folders can be renamed and moved.
  - Deleting a file or a folder (with everything in it) makes the content unreadable at once; the gateway then deletes the stored objects.
  - A folder can be shared, live, with one download limit for the whole share.

## Upgrading

There is no earlier release. Database migrations run up to `0018`. Migration `0016` renames files whose names clashed in the same place to "name (2).ext", and records each rename in the audit log.

## Known limits

- **AWS is exercised through LocalStack** locally and in CI. The Terraform modules target AWS, but this release has not run against a real AWS account.
- **Deletion can't be undone.** A database backup taken before a deletion still holds the file's key for as long as it is kept.
- **Node enrollment by GCP or Azure instance identity** is planned as a Plus, not built.
